### 1. Gaps: Missing Features, Failure Modes, and Edge Cases

1. **Agent Config Schema Drift & Upgrades:** CLI agents update frequently without deprecation cycles. An agent update renaming config keys (e.g., `mcpServers` to `mcp_servers`, or moving from `~/.claude.json` to `~/.claude/settings.json`) will cause `onesrc` writes to fail, clobber modern settings, or write dead keys.
2. **Concurrent Writes & Race Conditions:** If `onesrc sync` writes to a config file while Claude Code, Codex, or `agy` is running, the agent's exit handler or internal file-save (e.g., `claude mcp add` or state flush) will overwrite `onesrc`'s modifications, or vice versa.
3. **Symlink Fragility on Atomic Writes & Cross-OS/WSL:** 
   - Many CLI agents write configuration files via temp-file replacement (`write tmp -> rename`), which breaks symlinks by replacing the symlink with a plain file.
   - Symlinks crossing the WSL/Windows mount boundary (`/mnt/c/`) frequently fail due to NTFS permissions or path resolution bugs.
4. **Multi-Machine Desynchronization:** Storing `state.json` strictly in local `~/.config/onesrc/` means multi-machine sync via Git breaks. When Machine B pulls updates to `onesrc.toml`, it has no record of what was previously written into Machine B's agent configs, resulting in orphan keys or false conflict warnings.
5. **Remote & OAuth-Authenticated MCP Servers:** `[mcp.example-remote]` with `url = "..."` ignores authorization. Real-world remote MCP endpoints require Bearer tokens, dynamic OAuth authorization flows, or agent-managed headers. A static URL entry cannot handle dynamic token refresh.
6. **Skill Format & Frontmatter Incompatibilities:** Skills are not universal markdown files:
   - Antigravity requires directory-nested skills with YAML frontmatter (`name`, `description`) in `SKILL.md`.
   - Claude Code uses slash commands or plugin specs with different naming/tool bindings.
   - Symlinking a single source skill directory into multiple agents without schema/frontmatter adaptation will cause parsing errors in at least one agent.
7. **Instruction Collision & Clobbering:** The draft does not define how `AGENTS.md` and `fragments/<agent>.md` merge into targets that already contain user instructions. Appending without managed delimiters causes duplicate text on repeated runs; overwriting wipes out machine-specific instructions.

### 2. Wrong or Risky Assumptions

1. **Assumption: `serde_json` preserves formatting and comments.** Unlike `toml_edit`, standard `serde_json` discards JSON formatting, key ordering, indentation, and comments/JSONC syntax. Writing through `serde_json` will generate dirty diffs in user configs and strip comments.
2. **Assumption: `import` then `sync` is an automatic no-op.** Real agent configs have divergent MCP arguments, environment variables, and instruction phrasing. Merging them into a single canonical `onesrc.toml` requires manual conflict arbitration; an automatic round-trip no-op is mathematically impossible without per-agent override pollution.
3. **Assumption: Agents consistently expand environment variables.** Claude Code, Codex, and Antigravity handle `${VAR}` syntax in `env` blocks differently. Some pass strings literally to `exec`, some evaluate via shell, and others expect pre-resolved values. Assuming native support across all three will lead to broken MCP servers.
4. **Assumption: Skill symlinking is supported by all agents.** Several CLI file-watchers (`notify`/`inotify`) do not track symlink targets across file system boundaries or reload when target contents change.
5. **Assumption: Stable target paths exist.** File paths for early-stage tools like Codex CLI and Antigravity CLI differ based on OS, package manager (npm vs binary vs distro package), and execution context (WSL vs native Linux). Hardcoding or assuming simple defaults is risky.

### 3. Scope: What to Cut from v1, What is Missing from M0

#### What to Cut from v1:
1. **`onesrc add mcp ...` CLI command:** Editing `onesrc.toml` by hand is standard for dotfile managers. Building an interactive AST-preserving CLI writer for TOML before the sync engine is stable adds needless surface area.
2. **Bidirectional `import` with automated conflict resolution:** Complex 3-way merge logic will stall M0/M1. Defer automatic import; provide a read-only `onesrc inspect-agents` command that outputs suggested TOML snippets.
3. **Remote MCP servers:** Cut remote/URL MCP servers until local stdio servers are rock solid. Remote endpoints require auth/headers that break the current static data model.

#### What is Missing from M0:
1. **Target Detection & Path Probing Spec:** M0 needs an explicit schema and probe mechanism to detect CLI binary versions, config file locations, and formats across Linux/WSL/macOS.
2. **Data Contracts (Serde structs):** M0 must define exact Rust structs for `onesrc.toml` and `state.json`, including how managed entries are tracked.
3. **Delimiter Strategy for Managed Blocks:** M0 must specify the boundary markers (e.g., `# >>> ONESRC MANAGED >>>`) for instruction files so read-only `status` can reliably identify managed vs unmanaged text blocks.
4. **Visual Drift Diff Engine:** `status` in M0 needs a defined terminal output format (e.g., color-coded diff showing `Missing`, `Diverged`, and `Unmanaged` states).

### 4. Positioning vs Prior Art

- **Prior Art Analysis:**
  - `amtiYo/agents`: Focuses on repo-level `.agents/`; ignores user-level dotfiles and global configurations.
  - `eggboy/mcpshare`: Pure MCP synchronization; ignores skills, instructions, and secrets.
  - `spyrae/agentsync`: Rigid 1-way sync where Claude is the single source of truth; neglects non-Claude agents as first-class peers.
- **Is the niche real?** **Yes.** Power developers actively switch between Claude Code (daily coding), Codex CLI (batch/scripting), and Antigravity CLI (IDE/deep tasks). Managing instructions, skills, and MCP configurations independently across all three causes continuous drift.
- **Is it defensible?** **Fragile, but defensible if focused correctly:**
  - *Risk:* Industry standardization (e.g., widespread adoption of an open `AGENTS.md` standard or MCP registry specifications) could commoditize the instruction/MCP sync layers.
  - *Defense:* Position `onesrc` not as a simple copier, but as an **ownership-safe configuration linker with active drift detection**. Ownership tracking (`never touch unmanaged keys`), non-destructive atomic updates, and local secret resolution provide lasting utility even if config standards converge.

### 6. Top 5 Changes to DESIGN.md (Highest Value First)

1. **Replace Instruction File Overwrites/Symlinks with Delimited Managed Blocks:**
   Instead of symlinking or clobbering native files (`CLAUDE.md`, `GEMINI.md`), write instructions using distinct block delimiters (`<!-- ONESRC:START --> ... <!-- ONESRC:END -->`). This prevents destroying pre-existing agent-specific rules and eliminates format naming collisions.
2. **Swap `serde_json` for a Lossless/Format-Preserving JSON Parser:**
   Update the tech stack to use a CST or comment-preserving parser (e.g., `jsonc-parser` or `serde_json5`) for target JSON files. Standard `serde_json` will corrupt key order, erase indentation styles, and delete comments in user configs.
3. **Decouple Ownership Tracking from Local `state.json`:**
   Store ownership fingerprints directly in target files via metadata comments/hashes or maintain a portable lockfile (`onesrc.lock`) inside the source repo. This ensures that syncing the source repo across multiple machines (Linux, macOS, WSL) does not cause ownership loss.
4. **Demote `import` and Simplify M0 Scope:**
   Remove automated 3-way `import` from M0. Re-scope M0 to focus strictly on: agent environment discovery, target schema validation, and read-only drift reporting (`status`) against an explicitly declared `onesrc.toml`.
5. **Establish a Deterministic Secret Strategy (Wrapper vs. Inlined):**
   Acknowledge that agents (including Antigravity) do not uniformly expand `${VAR}` syntax in MCP configs. Explicitly document that `onesrc` resolves secrets from `secrets.env` at `sync` time, writes resolved values to target config files with restrictive permissions (`0600`), and logs clear warnings in `onesrc doctor`.
