The safety promises exceed what the proposed write protocol guarantees. M0 is the right starting point.

**1. New gaps / failure modes**

- **Ownership needs a baseline.** [DESIGN.md:145](../../DESIGN.md) (line 145 at commit 8394c21) records ownership but not what was last written. A user can subsequently edit an owned entry. Store its last-applied fingerprint; treat unexpected changes as conflicts, including during deletion. An existing unmanaged entry with the desired name must also conflict.
- **Targets and state cannot commit atomically together.** A crash after updating a target but before recording ownership leaves an unmanaged installation; the reverse can grant ownership incorrectly. Define a transaction journal, partial-success reporting, and recovery.
- **`undo` can destroy unrelated changes.** [DESIGN.md:135](../../DESIGN.md) (line 135 at commit 8394c21) restores a backup without checking subsequent agent/user edits. Undo should reverse owned changes conditionally against their post-apply baseline; refuse conflicts.
- **Secret handling starts too late.** `inspect` can print existing credentials into suggested TOML before M3 exists. Redaction must cover stdout, diffs, errors, backups, journals and probe artifacts from M0. Backups need private directories and retention rules. `doctor` cannot reliably recognize arbitrary literal secrets.
- **The example’s `~` is ambiguous.** [DESIGN.md:59](../../DESIGN.md) (line 59 at commit 8394c21) passes `"~/tools/..."` as an argument; ordinary process execution does not expand it. Specify source-relative paths, executable lookup, `cwd`, and explicitly supported substitutions.
- **Linked skills bypass sync.** Editing the source changes deployed skills immediately; an agent editing a linked skill changes the source repository. Define whether links intentionally provide live deployment and what `plan`/`undo` mean for them.
- **“Present” and “effective” differ.** An instruction override, disabled skill, project configuration or selected profile can shadow a correctly installed global entry. Report shadowing where observable; otherwise label status as file-level agreement.

**2. Triage verdicts / ADR disagreements**

- **Row 1.2; ADR-0002:** re-read → compare hash → rename is **not compare-and-swap**. Another writer can change the file after comparison. An agent can also overwrite the result later from cached state. Rename prevents torn files; it does not prevent lost updates. Describe optimistic conflict detection honestly, serialize onesrc writers, and define the supported policy for active agent writers.
- **Row 2.1; ADR-0002:** `preserve_order` plus matching indentation is not surgical JSON editing. Serialization can change whitespace, escapes and numeric representation throughout unrelated content. Choose either preservation of untouched byte ranges or a weaker, explicit semantic-preservation promise.
- **Row 1.6:** shared required frontmatter does not establish skill portability. Preserve the **whole directory**, including scripts, assets, executable bits and `agents/openai.yaml`. Define handling for agent-specific metadata and instructions referencing tools unavailable elsewhere.
- **ADR-0003:** “write the reference as-is” is insufficient. Codex uses field-specific environment-name references, not general `${VAR}` interpolation. Also, a value in `secrets.env` does not automatically enter an independently launched agent’s environment. Define provisioning and missing-variable behavior.

**4. Rust implementation risks**

- **JSON:** with `preserve_order`, `Map::remove()` still swaps another key into the removed position; use `shift_remove()`. Reject duplicate keys before constructing a map if ambiguous ownership is unacceptable. [Map behavior](https://docs.rs/serde_json/latest/serde_json/struct.Map.html#method.remove).
- **TOML:** retain the original `toml_edit` document; rebuilding through typed serialization defeats preservation. Test dotted keys, inline tables and comments attached to removed tables.
- **Symlinks:** Linux and macOS use the same Rust Unix symlink API. The difficult differences are filesystem behavior: default macOS case-insensitivity, Unicode-equivalent names, and WSL mount semantics. Reject destination collisions; use `symlink_metadata`/`read_link` to distinguish dangling links from absent files. Define handling of existing foreign symlinks.
- **Atomic replacement:** create the temporary file beside the destination, set its intended permissions **before writing secrets**, then write, sync and rename. Rename installs the temporary inode’s metadata; it does not inherit the destination’s mode, ACLs or extended attributes. `tempfile::persist()` does not synchronize either contents or the parent directory. [Persistence contract](https://docs.rs/tempfile/latest/tempfile/struct.NamedTempFile.html#method.persist).
- **Locking:** lock a stable, separate lockfile across planning/applying/state updates. Locking the destination inode becomes ineffective after replacement. Unix locks are advisory and cannot stop uncooperative agent writers. `std::fs::File` locking is available from Rust 1.89; declare an MSRV before selecting another crate. [Rust locking](https://doc.rust-lang.org/std/fs/struct.File.html#method.lock).
- **Distribution:** promise self-contained binaries per OS/architecture. “One static binary for Linux and macOS” is misleading; macOS binaries normally retain system-library dependencies.
